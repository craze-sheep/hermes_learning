# Physics Dataset Validation & Maintenance

For physics simulation datasets generated by Kubric/PyBullet, where each sample has `object_static.json` with object types and `video.json` with metadata.

## Workflow

### 1. Count object types from generation scripts (FAST)

Don't scan the database directly — it's too slow. Read the scripts instead:

```bash
for s in s1 s2 s3 s4 s5 s6 s7 s8; do
  script="task/task6-脚本编写/generate_${s}_dataset.py"
  types=$(grep -oP 'object_type="[^"]*"' "$script" | sort -u | tr '\n' ' ')
  echo "${s^^}: $types"
done
```

Get sample counts from LEVEL_TARGETS:
```bash
grep -oP 'LEVEL_TARGETS\s*=\s*\{[^}]+\}' "$script" | grep -oP ':\s*(\d+)' | grep -oP '\d+' | paste -sd+ | bc
```

### 2. Verify database consistency (SLOW — sample only)

```bash
# Sample check — don't scan all files
for s in S1 S2 S3 S4 S5 S6 S7 S8; do
  find database/$s -name "object_static.json" -maxdepth 3 | head -3 | xargs grep -h "object_type" | sort -u
done
```

### 3. Full validation script

Use `database/checkout/check_replace_object_types.py` if it exists — it scans all files and reports counts. Run without `--apply` first (dry-run).

### 4. Batch replace object types in database

```bash
# In the target directory
for d in */; do
  f="$d/object_static.json"
  [ -f "$f" ] && sed -i 's/"old_type"/"new_type"/g' "$f"
done
```

Also fix `video.json` metadata if it references the old type:
```bash
for d in */; do
  f="$d/video.json"
  [ -f "$f" ] && sed -i 's/old_name/new_name/g' "$f"
done
```

### 5. Update ALL related files (checklist)

When changing object types, update ALL of these:

**Scripts (task/task6-脚本编写/):**
- `generate_s*_dataset.py`: `*_spec()` function, `object_type` field, variable names, metadata strings in `make_cfg()`, type sets in `build_asset()`
- `validate_s*.py`: type sets in `if` conditions
- `physics_label_utils.py`: type sets in contact classification (e.g., wall_contact_sequence)
- `generate_parameter_visual_checks.py`: BodySpec type strings

**Data files (database/S*/L*/):**
- `object_static.json`: `"object_type"` field
- `video.json`: `level_name`, `subtask`, `main_variable` metadata fields

**Documentation (task/task3-数据集详细构成/):**
- `物体属性文档/参数详解.md`: object_type list, geometry parameters per type
- `type/S*_*/参数配置.md`: object_type pools, size ranges

### 6. Verify JSON structure consistency

All object types share the same 14-key schema in `object_static.json`:
```
object_id, segmentation_id, object_type, static
radius, size, height (geometric — varies by type)
mass
lateralFriction, rollingFriction, spinningFriction, restitution
color_name, rgba
```

Dynamic state (`object_dynamicjson/*.json`) has 9 keys:
```
object_id, time, visible_area
position, quaternion, velocity, angular_velocity, resultant force
segmentation_path
```

### 7. Use the verification script

```bash
# Dry-run (report only)
python database/checkout/check_replace_object_types.py

# Apply changes
python database/checkout/check_replace_object_types.py --apply
```

## Pitfalls

- **Database is huge** — never `grep -r` the full database without timeout. Use `maxdepth` and `head` to sample, or check scripts first.
- **video.json has metadata too** — level_name, subtask, main_variable may reference old type names. Fix with sed.
- **Variable names vs type strings** — changing `object_type="wall"` is not enough; also rename `obstacle_sizes` → `wall_sizes` etc. for consistency.
- **PyBullet shape mapping** — in `build_asset()`, the type set `{"cube", "ground", "wall"}` maps to `kb.Cube`. Verify this set matches your type map after changes.
- **Function naming conflicts** — if renaming `obstacle_spec` to `wall_spec` but `wall_spec` already exists with different defaults, use a descriptive name like `blocking_wall_spec` instead.
- **Checkpoint compatibility** — changing `attr_dim` (e.g., 14→13) breaks old checkpoints. Must retrain.
