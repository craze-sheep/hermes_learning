# Dataset Validation for Physics Simulations (Kubric/Blender)

Validate datasets generated by Kubric (Blender + PyBullet) for correctness of depth maps, segment masks, metadata, and rendering artifacts.

## When to Use

- After generating a batch of simulation samples, before committing to training
- When suspecting rendering bugs (e.g., corrupted depth, misaligned segments)
- As a QA gate before large-scale dataset production

## Directory Structure (Expected)

```
S{x}/L{y}/{id}/
  {id}.mp4              # rendered video
  {id}.npz              # depth map (keys: depth [T,H,W] float32, unit [str])
  video.json            # metadata: fps, num_frames, camera, units
  object_static.json    # list of object definitions (id, type, static/dynamic, physics params)
  dynamic/{frame}/
    {frame}.png          # rendered RGB frame (H,W,3) uint8
    force_matrix.json    # inter-object forces per timestep
    object_segment/
      {obj_id}.npz       # mask (H,W) uint8 {0,1}, object_id, segmentation_id, frame_num
    object_dynamicjson/
      {obj_id}.json      # per-frame physics: position, velocity, force, visible_area

NOTE: physics_labels.json was deliberately removed from all S1-S8 scripts.
The dataset is for causal learning — pre-computed summary labels would leak
outcome information. Raw trajectory data (object_dynamicjson) contains all
needed information. S8 retains `no_dynamic_collision` check at generation
time (via compute_physics_labels import) but does NOT write the file.
```

## Validation Steps

### Step 1: Structure Completeness

Check that every expected file exists for each sample. Missing files indicate interrupted rendering.

```python
import os
required_exts = ['.mp4', '.npz', 'video.json', 'object_static.json']
# Also check dynamic/{frame}/ has .png, object_segment/, object_dynamicjson/
```

### Step 2: Depth Map Sanity

The most common failure mode. Check:

```python
import numpy as np
d = np.load(f"{id}.npz")['depth']
# Expected shape: (num_frames, H, W), dtype float32
# Check for:
#   - inf/nan values
#   - Unrealistic values (>100m for typical scenes, camera at ~8m)
#   - Blender far-clipping-plane artifacts (~1e10)
#   - Frame-to-frame consistency (depth should change smoothly)
```

**⚠️ Background depth is NOT a bug**: Blender assigns ~10^10 meters to background/sky pixels. This is expected behavior. Distinguish between:

| Scenario | depth.max() | Foreground separation | Status |
|----------|------------|----------------------|--------|
| Clean render with background | ~1e10 | `depth[(depth > 20) & (depth < 1e9)]` = 0 pixels | ✅ Expected |
| Far-plane corruption bug | ~1e10 | Foreground/background boundary has artifacts | ❌ Bug |
| All foreground (top orthographic) | < 20 | No background pixels at all | ✅ Expected |

Validation pattern:
```python
bg_mask = depth > 1e9
fg_mask = (~bg_mask) & (depth > 0)
transition = depth[(depth > 20) & (depth < 1e9)]
if len(transition) > 0:
    report("depth transition artifacts")  # actual bug
# bg_mask.sum() being large is fine — just background
```

**Known pattern**: depth corruption can be strongly correlated with sample ID (e.g., all odd IDs, or every 3rd ID). Always check for ID-correlated patterns:

```python
from collections import Counter
bad_ids = [sid for sid, d in zip(all_ids, all_depths) if d.max() > 100]
# Check mod patterns
for mod in range(2, 6):
    dist = Counter(i % mod for i in bad_ids)
    print(f"mod {mod}: {dict(dist)}")
```

### Step 3: Segment Mask Validation

```python
seg = np.load(f"dynamic/{frame}/object_segment/{obj_id}.npz")
# Expected: mask shape (H,W), dtype uint8, values {0,1}
# Check:
#   - mask.shape matches depth H,W
#   - No overlap between different object masks
#   - frame_num matches directory name
#   - object_id/segmentation_id matches object_static.json

overlap = np.logical_and(seg1['mask'], seg2['mask'])
assert overlap.sum() == 0, "Masks overlap!"
```

### Step 4: Physics Stopping Time Check

**NOTE: physics_labels.json has been removed from all S1-S8 scripts.**
The `is_static_at_end` / `stop_frame` / `travel_distance` fields are no
longer written to disk. To check stopping time post-hoc, compute from raw
trajectory data in `object_dynamicjson/`:

```python
import json, numpy as np
# Read last frame's dynamic json for the primary object
with open("dynamic/36/object_dynamicjson/2.json") as f:
    final = json.load(f)
speed = np.linalg.norm(final["velocity"])
if speed > 0.5:
    report(f"Object still moving at {speed:.2f} m/s")
# Threshold: 0.05 m/s (matches old is_static_at_end logic)
```

Known stopping issues (from S2 validation before removal):
- **S2 L6 spheres** (rolling friction): 32% don't stop in 3s, worst 2.14 m/s
- **S2 L7 lying cylinders**: 23% don't stop in 3s, worst 7.16 m/s
- **S2 L4/L5**: <3% don't stop, speed ~0.02 m/s (marginal, acceptable)

Root cause: 3-second simulation (36 frames @ 12fps) is insufficient for objects with low rolling friction. Not a code bug — a physics constraint. Fix: increase `DURATION_S` or accept partial-stopping data.

### Step 5: View-Specific Depth Characteristics

Different camera types produce very different depth distributions. Don't apply the same threshold to all views:

| Camera Type | Typical foreground % | background | Notes |
|------------|---------------------|------------|-------|
| Perspective front | 30-60% | ~1e10 m | Large background area visible |
| Orthographic top | 100% | none | Entire image is scene |
| Perspective side | 50-70% | ~1e10 m | Different FOV than front |

When validating, group samples by view and apply view-specific checks:
```python
# Group by view (typically ID % n_views)
for view_idx in range(n_views):
    view_samples = [s for s in samples if int(s.id) % n_views == view_idx]
    # Apply view-specific depth expectations
```

### Step 6: Cross-Field Consistency

```python
import json
vid = json.load(open("video.json"))
# vid['num_frames'] should match depth.shape[0]
# vid['cameras'][0]['resolution'] should match depth.shape[1:3]
# vid['cameras'][0]['depth_path'] should match the npz filename

static = json.load(open("object_static.json"))
# len(static) should match number of object_segment/*.npz files per frame
# segmentation_id in static should match segmentation_id in segment npz
```

### Step 7: Geometric Overlap / Embedding Detection

When a dynamic object is placed on or near a static object, it may clip into the geometry. Blender's segmentation layer assigns overlapping pixels to the front-most surface, so the embedded object gets mask=0 even though it's visible in the RGB render.

```python
# For each sample, check if any dynamic object has visible_area=0 in ALL frames
import json
for obj_id in dynamic_object_ids:
    all_zero = True
    for frame in range(1, 37):
        with open(f"dynamic/{frame}/object_dynamicjson/{obj_id}.json") as f:
            dyn = json.load(f)
        if dyn["visible_area"] > 0:
            all_zero = False
            break
    if all_zero:
        # Suspect embedding — verify with vision_analyze on the RGB frame
        # Also compare z-position with enclosing object's top surface
        report(f"obj {obj_id}: visible_area=0 for all 36 frames (suspect embedding)")
```

Cross-check with all views of the same physical sample: if the object is invisible from ALL camera angles (front, top, left), it's almost certainly embedded rather than out-of-frame.

### Step 8: Visual Overlay Verification

Overlay segment masks on rendered frames to verify spatial alignment:

```python
from PIL import Image
import numpy as np

png = np.array(Image.open(f"dynamic/{frame}/{frame}.png"))
seg1 = np.load(f"dynamic/{frame}/object_segment/1.npz")['mask']
seg2 = np.load(f"dynamic/{frame}/object_segment/2.npz")['mask']

vis = png.copy()
vis[seg1 > 0] = [255, 0, 0]    # red = object 1
vis[seg2 > 0] = [0, 255, 0]    # green = object 2
Image.fromarray(vis).save(f"/tmp/overlay_{frame}.png")
# Then use vision_analyze to check alignment
```

## Pitfalls

1. **Blender far-plane values (~1e10)**: Background/sky pixels get ~10^10m depth — this is EXPECTED, not a bug. Only flag as bug if foreground/background boundary has transition artifacts (pixels between 20m and 1e9m). Use `depth[(depth > 20) & (depth < 1e9)]` to detect real corruption.
2. **ID-correlated depth patterns**: If depth stats vary by sample ID (e.g., all odd IDs have different background %), check if it's view-dependent rather than a bug. Different camera types (front vs top) legitimately produce different depth distributions. Group by `ID % n_views` and check each view independently.
3. **Ground mask covers ~99% in top-view**: For orthographic top-down cameras, the ground plane occupies nearly the entire image. This is correct, not a bug.
4. **Small object masks in perspective view**: Objects far from camera may have only 10-100 pixels. This is expected for 128x128 resolution with perspective cameras.
5. **Kubric Cylinder class**: `kb.Cylinder` works in the official Docker image (`kubricdockerhub/kubruntu`) but may not exist in older local installs. If using Cylinder and getting errors, verify the Docker image version. L7 data confirmed working with `kb.Cylinder(scale=(radius, radius, height/2.0))`.
6. **Unit field**: depth unit is stored as a string in the npz (e.g., 'm' for meters). Always verify it matches video.json units.
7. **Docker OOM Kill**: WSL2 with ≤8GB RAM + Blender rendering (~1.6GB per container) is at high OOM risk. Check `dmesg -T | grep -i oom` when containers disappear unexpectedly. Docker `--rm` flag makes killed containers vanish without a trace.
8. **PyBullet ground penetration**: High-speed spheres with small radius and low rolling friction can penetrate the ground plane. Check `z_final < 0` in sphere scenarios. Example: S2 L6 had 33/324 spheres with z_final < 0 (worst: -2.94m).
9. **Empty directories on generation failure**: When a sample generation fails mid-way (e.g., OOM kill), empty directories may be left behind. Always check for `<scenario>/<level>/<id>/` with 0 files inside.
10. **Orthographic top-view mask invariance**: Sphere masks in orthographic top view do NOT change with height (the projected circle is always the same size). This is correct behavior, not a bug. Front/perspective views SHOULD show mask movement.
11. **physics_labels.json removed**: This file was deliberately removed from S1-S8 scripts (May 2026). The dataset targets causal learning — pre-computed labels leak outcome info. S8 retains the `compute_physics_labels` import solely for `no_dynamic_collision` filtering at generation time. If you need summary labels for evaluation/debug, compute from raw `object_dynamicjson/` data post-hoc.
12. **Object embedding causes segmentation all-zeros**: When a dynamic object (e.g. cube) is placed on a ramp surface, the placement logic may position it INSIDE the ramp geometry. Blender's segmentation layer assigns overlapping pixels to the front-most surface only, so the embedded object gets mask=0 for ALL frames and ALL views — even though it's visually visible in the RGB render. **Detection**: compare `visible_area` across all 3 views of the same physical sample; if all are 0, check object z-position vs enclosing object's top surface. **Root cause**: `ramp_surface_point` returns the ramp's geometric center, not its outer surface; the normal offset `cube_half_height` doesn't account for ramp thickness. **Fix**: add `ramp_half_thickness * cos(angle)` to the normal offset. See `references/s3-ramp-embedding-bug.md`.

## Batch Statistics Script

For large-scale validation, aggregate across all samples:

```python
import os, numpy as np
base = "database/S{x}"
results = {'total': 0, 'depth_bad': 0, 'missing_seg': 0}
for lvl in sorted(os.listdir(base)):
    for sid in sorted(os.listdir(os.path.join(base, lvl))):
        npz = os.path.join(base, lvl, sid, f"{sid}.npz")
        if os.path.exists(npz):
            results['total'] += 1
            d = np.load(npz)['depth']
            if d.max() > 100:
                results['depth_bad'] += 1
print(results)
```
